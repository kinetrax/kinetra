Executive Summary

KinetraX is a decentralized sport platform that connects trainers with athletes through the TON (The Open Network) blockchain. Built as a Telegram Mini App, KinetraX enables seamless session booking, transparent payments, and automatic revenue distribution using smart contracts. The platform eliminates intermediaries, reduces transaction costs, and provides a trustless environment for sport professionals and participants.

1. Introduction

1.1 The Problem

The sport industry faces several challenges:

  • High Transaction Fees: Traditional payment processors charge 2.5-3.5% per transaction, reducing trainer earnings
  • Payment Delays: Coaches often wait days or weeks to receive payments
  • Lack of Transparency: Complex fee structures and unclear commission models
  • Limited Accessibility: Geographic barriers and platform lock-ins restrict trainer-audience connections
  • Trust Issues: No automated verification of bookings and attendance

1.2 Our Solution

KinetraX leverages blockchain technology to create a transparent, efficient, and cost-effective marketplace for sport sessions. By using TON blockchain smart contracts, we enable:

  • Instant Payments: Automated payment processing with minimal fees
  • Transparent Revenue Sharing: Smart contracts automatically distribute payments between trainers and the platform
  • Trustless Bookings: Blockchain-verified registrations and participant verification
  • Global Accessibility: Telegram Mini App format enables worldwide access
  • Low Transaction Costs: TON blockchain's efficiency keeps costs minimal

2. Platform Architecture

2.1 Technology Stack

Frontend:

  • React 18 with TypeScript
  • Telegram Mini Apps SDK
  • Tailwind CSS for styling
  • MapTiler for location services

Backend:

  • Fastify web framework
  • TypeScript
  • TypeORM for database management
  • PostgreSQL for persistent data storage
  • Redis for caching and performance optimization

Blockchain:

  • TON (The Open Network) blockchain
  • Tolk smart contract language
  • TON Connect for wallet integration

2.2 System Architecture

KinetraX operates as a three-tier system:

  1. Presentation Layer: Telegram Mini App (React frontend)
  2. Application Layer: RESTful API (Fastify backend)
  3. Blockchain Layer: TON smart contracts for payments

3. Core Features

3.1 User Management

Telegram Authentication:

  • Seamless authentication via Telegram Web App
  • No separate account creation required
  • User profiles automatically linked to Telegram accounts

User Profiles:

  • Professional profiles with description (minimum 100 characters)
  • Session statistics (sessions conducted as trainer, sessions participated as athlete)
  • Profile viewing and editing capabilities

3.2 Session Management

Session Creation:

Trainers can create sport sessions with:

  • Session name and type (e.g., "Yoga", "CrossFit", "Running")
  • Detailed description
  • Location (GPS coordinates)
  • Date and time
  • Duration (in minutes)
  • Price (in TON)
  • Number of available slots
  • Wallet address for receiving payments

Session Discovery:

  • Interactive map interface showing all available sessions
  • Location-based filtering
  • Real-time availability display
  • Session type filtering

Session Management:

  • View session details
  • Update session information (name, description, time, price, location, slots)
  • Delete sessions
  • View participant lists

3.3 Booking System

Session Registration:

  • Athletes can browse and join available sessions
  • Real-time slot availability checking
  • Automatic wallet connection via TON Connect
  • Blockchain-verified payment processing

Participant Verification:

  • Unique participant codes generated for each booking
  • SHA-256 hash-based code generation
  • Coach-verifiable codes for session attendance
  • Secure code validation system

3.4 Payment System

Smart Contract Architecture:

The platform uses a TON smart contract (Session Payment Contract) that handles:

  • Payment Reception: Receives payments from participants
  • Automatic Distribution: Splits payment between trainer and platform
  • Commission Management: Configurable commission rate (default: 2% = 200 basis points)
  • Transparent Transactions: All transactions recorded on blockchain

Payment Flow:

  1. Participant initiates payment via TON Connect wallet
  2. Payment sent to smart contract with coach wallet address
  3. Smart contract calculates commission (e.g., 2% of payment)
  4. Coach receives payment minus commission
  5. Platform receives commission
  6. Transaction recorded on TON blockchain

Commission Model:

  • Default commission rate: 2% (200 basis points)
  • Configurable by platform owner
  • Commission rate range: 0-100% (0-10,000 basis points)
  • Platform wallet address configurable

3.5 Session History

Past Sessions:

  • View all completed sessions
  • Filter by user participation (as trainer or participant)
  • Chronological ordering (newest first)

Upcoming Sessions:

  • View all future sessions user is involved in
  • Filter by user participation (as trainer or participant)
  • Chronological ordering (soonest first)

4. Blockchain Integration

4.1 TON Blockchain Benefits

Why TON?

  • High Throughput: Can handle millions of transactions per second
  • Low Fees: Minimal transaction costs (fractions of a cent)
  • Fast Finality: Near-instant transaction confirmation
  • Scalability: Built for mass adoption
  • Telegram Integration: Native support for Telegram ecosystem

4.2 Smart Contract Features

Session Payment Contract:

  • Written in Tolk language
  • Handles payment distribution automatically
  • Owner-controlled configuration
  • Transparent and auditable

Contract Methods:

  • getPlatformWallet(): Returns platform wallet address
  • getCommissionRate(): Returns current commission rate
  • getOwner(): Returns contract owner address
  • onInternalMessage(): Handles payment processing

Security Features:

  • Owner-only settings updates
  • Input validation for all parameters
  • Error handling for invalid transactions
  • Payment requirement validation

4.3 Wallet Integration

TON Connect:

  • Native Telegram wallet support
  • External wallet compatibility
  • Secure transaction signing
  • User-friendly payment flow

5. User Experience

5.1 Telegram Mini App

Accessibility:

  • Available within Telegram app
  • No separate app installation required
  • Cross-platform compatibility (iOS, Android, Web)
  • Instant access via Telegram bot or link

User Interface:

  • Modern, clean design
  • Mobile-optimized layout
  • Intuitive navigation
  • Real-time updates

5.2 Key User Flows

For Trainers:

  1. Sign up and create profile
  2. Create sport session with details
  3. Share session or wait for bookings
  4. Receive payments automatically to wallet
  5. Verify participants using codes
  6. View session statistics

For Athletes:

  1. Browse sessions on map
  2. View session details
  3. Connect wallet and pay
  4. Receive participant verification code
  5. Attend session and provide code
  6. View session history

6. Revenue Model

6.1 Commission Structure

Platform Revenue:

  • Commission from each session booking
  • Default rate: 2% of session price
  • Adjustable by platform governance
  • Received in TON cryptocurrency

Revenue Distribution:

  • 98% to trainer (coach wallet)
  • 2% to platform (platform wallet)

6.2 Cost Structure

Transaction Costs:

  • TON blockchain fees: Minimal (typically <$0.01 per transaction)
  • No credit card processing fees
  • No payment gateway fees
  • No currency conversion fees

8. Security & Privacy

7.1 Security Measures

Blockchain Security:

  • Immutable transaction records
  • Smart contract code auditable
  • No central point of failure
  • Decentralized payment processing

Application Security:

  • Type-safe codebase (TypeScript)
  • Input validation on all endpoints
  • Secure participant code generation
  • Protected API endpoints

Data Privacy:

  • User data stored securely
  • Telegram authentication (no password storage)
  • Location data only stored for session purposes
  • GDPR-compliant data handling principles

7.2 Participant Verification

Code Generation:

  • SHA-256 hash-based codes
  • Deterministic generation (same input = same code)
  • Unique per user-session combination
  • 8-character uppercase codes

Verification Process:

  • Coaches can validate participant codes
  • Codes linked to registered participants
  • Secure validation endpoint
  • Prevents unauthorized access
